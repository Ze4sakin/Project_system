## 1. 背景与目标

### 1.1 要解决的问题

现有工具要么太重（Jira/禅道，字段和流程让一线不愿填），要么太散（Excel + 群聊，数据不实时、进度靠人问）。核心矛盾是：**管理层要"看得见的进度"，一线要"少填表"。**

### 1.2 产品定位

一个"填得动、看得清"的轻量项目管理系统：以 **计划（任务）** 为唯一数据主干，需求与缺陷挂在计划上，甘特图与仪表盘都是主干的视图，不做第二套数据。

### 1.3 目标（可衡量）

| 目标 | 衡量方式 |
| --- | --- |
| 一线愿意填 | 单任务更新 ≤ 2 次点击 / 10 秒内完成 |
| 进度可信 | 仪表盘进度全部由任务数据计算，不允许手填 |
| 延期可视 | 任务延期当天进入提醒队列，次日可查 |
| 起步快 | 用模板 3 分钟建出一个可执行项目 |
| 复用强 | 一个项目可完整另存为模板，跨项目复用 |

### 1.4 不做的事（Non-goals，v1）

- 不做工时计费、财务预算、成本核算
- 不做工时填报（v1 仅记录任务进度与周报，决策 #3）
- 不做多人协作、账号体系与组织架构（个人使用形态，决策 #4）
- 不做 OKR / 绩效管理
- 不做代码仓库、CI/CD 深度集成（仅保留链接字段）
- 不做多级审批流引擎（复盘只做记录与导出，无审批、无确认人）
- 不做敏捷燃尽/看板的完整 Scrum 套件（仅提供列表 + 甘特 + 简约看板视图）

## 2. 核心概念与对象模型

```
项目 Project
 ├── 计划 Plan（阶段 / 里程碑 / 任务，树形）
 │     ├── 需求 Requirement（可关联 0..N 个任务）
 │     └── 缺陷 Defect（关联需求或任务，0..1）
 ├── 复盘 Review（每日快记 / 周复盘）
 ├── 提醒 Notification（由规则触发）
 └── 仪表盘 Dashboard（视图，不持有独立数据）
```

**一条铁律：进度只有一个来源。** 所有百分比都从任务计算，需求/缺陷/阶段/项目均为聚合值，禁止手工录入进度（允许手工录入"完成标志"）。

### 2.1 对象最小字段集

**项目 Project**：名称、编号、负责人、起止日期、状态（未开始/进行中/已延期/已完成/已归档）、模板来源、健康度（自动算）。

**任务 Task**：标题、所属阶段、负责人、计划开始/结束、预计工时、实际进度%、状态、优先级、前置任务、里程碑标记、基线日期（建项目时快照）。

**需求 Requirement**：编号、标题、描述、来源、优先级（P0-P3）、状态、负责人、期望上线日、关联任务。

**缺陷 Defect**：编号、标题、严重级别（致命/严重/一般/轻微）、状态、负责人、发现版本、关联需求、创建/关闭时间。

**复盘 Review**：类型（每日快记 / 周复盘）、周期、内容（自动数据摘要 + 手写三栏）、导出记录、保存时间、关联项目。无"提交人/确认人"字段。

## 4. 模块详述

### F1 计划（任务主干）

**目标**：让一线用一张表管完所有活。

**功能点**

1. **树形结构**：项目 → 阶段（可多层，建议≤3 层）→ 任务 → 子任务。支持一键折叠、拖拽调整层级与顺序。
2. **快速新建**：表格内回车即新建下一行；支持粘贴 Excel 多行批量导入（列顺序：标题/负责人/开始/结束/工时/优先级）。
3. **内联编辑**：除描述外所有字段在列表内直接改，不弹窗（轻量原则关键点）。
4. **状态**：未开始 / 进行中 / 阻塞 / 已完成 / 已取消。切到"阻塞"必须填阻塞原因（一个必填项，用于仪表盘风险汇总）。
5. **依赖关系**：支持"完成-开始（FS）"一种依赖（v1 只做最常用的一种，避免复杂），支持设置提前/延后天数。
6. **里程碑**：标记为里程碑的任务在甘特图上以菱形显示，不参与进度加权。
7. **批量操作**：批量指派负责人、批量改期（顺延 N 天）、批量改状态。
8. **进度更新**：滑块或 0-100 输入；也支持"按子任务完成比例自动算父级"。
9. **基线**：项目首次排期确认时生成基线快照（可重设，重设需记录原因），用于甘特图对比与延期判定。

**规则**

- 父任务进度 = Σ(子任务预计工时 × 子任务进度) / Σ(子任务预计工时)；无工时时按任务数平均。
- 任务预计工时为空时，聚合时按 1 计（避免被 0 稀释）。
- 任务状态与进度联动：进度 100% → 自动置"已完成"；状态改"已完成" → 进度自动 100%。允许手动回退。

### F2 甘特图

**目标**：一屏看清"什么时候干什么、卡在哪"。

**功能点**

1. **双栏布局**：左侧任务树（与 F1 同一份数据、同步滚动），右侧时间轴。
2. **时间粒度**：日 / 周 / 月三档切换；支持缩放到"季度"总览。
3. **拖拽排期**：拖条移动整体日期、拖两端改工期；改动即时回写任务字段，并弹出"是否顺延后续依赖任务"。
4. **依赖箭头**：FS 依赖连线；依赖冲突（前置未完成而后置已开始）标红。
5. **关键路径**：按依赖链 + 工期自动计算，关键路径上的条以深色描边显示。
6. **基线对比**：显示基线灰条 + 当前彩条，一眼看出"计划 vs 实际"。
7. **今日线**：一条竖线，右侧为未来。过期未完成的任务条末端加红色斜纹。
8. **里程碑泳道**：顶部单独一条里程碑轴，聚合展示所有菱形，便于对节点。
9. **进度填充**：任务条内部按进度填充，未开始/进行中/延期用不同色（延期=红，阻塞=橙，正常=蓝，完成=灰）。

**性能要求**：单项目 1000 个任务时，首屏渲染 ≤ 1.5s，拖拽响应 ≤ 100ms（虚拟滚动 + Canvas/SVG 混合渲染）。

### F3 需求

**目标**：需求不丢、可追溯、能对上计划。

**功能点**

1. **需求池**：项目内需求列表，支持按状态/优先级/负责人/来源筛选，支持关键词搜索。
2. **状态流转**：草稿 → 待评审 → 已通过 → 开发中 → 已上线 → 已验收 / 已关闭；驳回回到草稿。每次流转记录人与时间。
3. **优先级**：P0（必做，阻塞上线）/ P1（重要）/ P2（一般）/ P3（可延后）。
4. **需求 ↔ 任务关联**：一个需求可拆多个任务；一个任务原则上只挂一个需求。关联后在需求详情里看到"关联任务进度汇总"。
5. **需求覆盖率**：仪表盘指标 = 已关联任务的需求数 / 已通过需求数，用于发现"评了但没排期"的需求。
6. **需求变更记录**：字段改动留痕（谁、何时、改了什么），支持"需求变更次数"统计（反映需求稳定性）。
7. **轻量评论**：引用任务 / @任务 + 附件（图片/文件），不做富文本编辑器（用 Markdown 简版）；个人使用下无"@同事"。

### F4 缺陷

**目标**：缺陷能登记、能追、能算账。

**功能点**

1. **缺陷登记**：标题、严重级别、复现步骤（纯文本）、发现版本、环境、指派人、关联需求/任务、附件（截图）。
2. **严重级别**：致命（系统不可用/数据错误）/ 严重（主流程阻断）/ 一般（功能异常有绕过）/ 轻微（UI/文案）。
3. **状态流转**：新建 → 已确认 → 修复中 → 待验证 → 已关闭；支持"重开"（回"已确认"）与"不予处理"（需填理由）。
4. **快速登记**：全局"+"按钮，3 个必填项（标题、严重级别、项目）即可创建，其余后补。
5. **缺陷指标**：新增数、关闭数、存量（未关闭）、重开率、缺陷密度（缺陷数 / 已完成任务数）、平均修复时长。
6. **缺陷 ↔ 需求关联**：按需求维度看"这个需求的质量"。
7. **与计划的联动**：缺陷可一键转为修复任务（生成关联任务并排入计划），避免缺陷和计划两张皮。

### F5 项目仪表盘

**目标**：3 秒回答"这个项目现在怎么样"。

**页面结构（自上而下）**

1. **项目头部**：项目名、负责人、周期、状态徽标、健康度灯（红/黄/绿）、"距上线 N 天"。
2. **四张核心卡**
   - **整体进度**：计划进度 vs 实际进度（双环或双条），偏差百分点。
   - **任务概览**：总数 / 已完成 / 进行中 / 未开始 / 延期 / 阻塞。
   - **需求概览**：已通过数 / 已上线数 / 覆盖率 / 变更次数。
   - **缺陷概览**：存量 / 本周新增 / 本周关闭 / 致命+严重存量。
3. **进度趋势图**：折线（计划进度基线 vs 实际进度），按周采样，看"是否越走越偏"。
4. **延期清单（Top 10）**：按延期天数倒序，字段：任务、负责人、计划完成、延期天数、阻塞原因、所属阶段。可一键催办。
5. **复盘状态**：本周是否已复盘 / 上次复盘距今几天 / 连续复盘周数。未复盘只在角落显示一个淡色点，**不出红字、不显示"未完成名单"**（反打卡，见 F7.1）。
6. **风险与提醒区**：由提醒规则产生的待处理项（延期、依赖冲突、需求未排期、复盘待写）。

**布局可配**：卡片可拖拽排序、可隐藏，布局可存为模板（见 F8）。默认给出"负责人视图 / 管理层视图"两套预设。

**关键指标口径（必须统一，避免争议）**

| 指标 | 计算公式 |
| --- | --- |
| 计划进度 | Σ(任务计划工时按时间应完成比例) / Σ工时，即"到今天按基线应完成多少" |
| 实际进度 | Σ(任务预计工时 × 进度%) / Σ预计工时 |
| 进度偏差 | 实际进度 − 计划进度（负数=落后） |
| 按期完成率 | 按期完成任务数 / 已到期任务数 |
| 健康度 | 绿：偏差 ≥ −5% 且 无致命缺陷且延期任务占比 <10%；黄：偏差 −5%~−15% 或 延期占比 10%~25% 或 有严重缺陷；红：超出以上 |
| 缺陷密度 | 缺陷总数 / 已完成任务数 |

### F6 设置中心

**目标**：能按团队习惯改，但不至于改到失控。

**功能点**

1. **项目设置**：基础信息、归属标签（替代成员角色）、归档/删除（软删除，30 天可恢复）。
2. **状态自定义**：任务/需求/缺陷各自的状态集合可增删改（含排序、颜色、是否终态）。**限制**：必须有且仅有一个"初始状态"与至少一个"终态"；已使用的状态不可直接删除，只能停用。
3. **字段自定义**：项目级自定义字段（文本/数字/日期/单选/多选/标签），可设为"必填"和"是否在列表显示"。不做公式字段（v1）。
4. **提醒规则**：场景化配置，见 F9。
5. **复盘规则**：见 F7.8。
6. **模板管理**：项目模板、阶段模板、需求/缺陷模板、复盘导出模板、仪表盘布局模板的增删改与设为默认。
7. **数据与导出**：全项目导出 Excel/CSV；提供"数据字典"查看当前字段定义。

### F7 复盘中心（自我复盘总结）

**目标**：把"每周写周报"变成"每周看一眼自己的战绩，留一句判断"。

#### F7.1 设计前提（为什么它不是提交系统）

原来的"提交中心"解决的是"让别人知道进度"，需要第二个人接收。个人使用形态下没有第二个人，这套机制会退化成**给自己打卡**——而打卡一旦被考核化，内容必然敷衍。

因此本模块的定位是：**系统的数据 + 我的判断 = 一份可回看的复盘**。三条反打卡原则：

| 原则 | 具体做法 |
| --- | --- |
| 不考核 | **不统计"提交率"、不生成"未提交名单"、不做逾期惩罚** |
| 不催办 | 提醒最多一次，错过就错过，不补发、不升级 |
| 不强制长文 | 手写部分只有 3 个框，每框一句话也算完成 |

> 判断标准很简单：如果某天忙得没写，第二天打开时**不会看到一片红色警告**——那这套设计就对了。

#### F7.2 两类记录

| 类型 | 何时用 | 内容 | 耗时 |
| --- | --- | --- | --- |
| 每日快记（可选） | 当天收工前 | 一句进展 + 一句卡点 | 30 秒 |
| 周复盘（核心） | 每周固定日 | 自动汇总本周数据 + 手写三栏反思 | 3 分钟 |

#### F7.3 自动汇总（这部分不需要手填）

打开复盘页时，以下数据块已自动生成，只需确认或删除：

1. **本周完成**：已完成任务清单 + 数量 + 预计工时合计
2. **本周推进**：进度有变化但未完成的任务，显示"从 X% → Y%"
3. **延期变化**：本周新增延期 / 本周解除延期（这是最有价值的信号）
4. **需求流动**：本周新通过、新上线、新变更的需求
5. **缺陷流水**：本周新增 / 关闭 / 现存致命与严重数
6. **进度对比**：计划进度 vs 实际进度，与上周的偏差变化
7. **里程碑**：本周达成 / 出现风险 / 已延期
8. **环比箭头**：上述每个数字与上周对比的升降

> 汇总口径与其他模块完全一致（见 F5 指标口径表），不另算一套。

#### F7.4 手写三栏（只有三个框）

| 栏目 | 提示文案 | 必填 |
| --- | --- | --- |
| 本周做成了什么 | "写 1–3 条，哪怕很小" | 否 |
| 卡在哪、为什么 | "可从阻塞任务一键带入原因" | 否 |
| 下周最重要的一件事 | "只写一件" | 否 |

设计约束：

- 三栏均为纯文本，不做富文本编辑器
- 支持 `@任务` 引用（输入 `@` 弹出本项目未完成任务，选中后变成可点击标签）
- 每栏上限 500 字，超出提示"精简一下，复盘不需要归档所有细节"
- **全空也能保存**（只留数据快照），但会提示"这次只留了数据，下次加一句话会更好"

#### F7.5 复盘时间线

- 按周倒序的纵向时间轴，每条卡片显示：周次、完成数、进度偏差、手写摘要首行
- 支持按项目筛选、按"仅看有手写内容"过滤
- 点击展开完整复盘；可对比任意两周（看"我当时怎么判断的"）
- **连续复盘周数（streak）** 以小字显示在顶部，只作鼓励，断档不清零成红色、不提示"你已中断"

#### F7.6 一键导出（对外汇报用）

这是个人场景下复盘最实用的出口——把内部复盘变成对外的周报。

| 项 | 说明 |
| --- | --- |
| 格式 | Markdown / 纯文本，一键复制到剪贴板 |
| 可勾选内容块 | 数据摘要 / 手写反思 / 下周计划 / 关联任务清单 / 附件 |
| 导出模板 | 2 套内置：「简洁版」（3 段话）与「详实版」（带数据表）；可自定义（存进 F8 模板体系） |
| 敏感信息 | 导出前可勾选"隐藏内部任务名"，只保留分类统计 |
| 历史 | 导出记录留存，避免重复导出同一周 |

#### F7.7 快照留痕

每次保存复盘时生成不可变快照（当时的项目数据 + 手写内容 + 保存时间）。后续任务数据变化**不回写历史**——因为复盘的价值正在于"当时我是基于什么信息做的判断"。

#### F7.8 复盘规则配置（在 F6 设置中心内）

| 配置项 | 说明 | 默认 |
| --- | --- | --- |
| 复盘日 | 每周几、几点提醒 | 周五 18:00 |
| 覆盖范围 | 哪些项目进入周复盘 | 全部进行中项目 |
| 提醒次数 | 站内提醒最多推几次 | 1 次 |
| 自动起草 | 打开即生成数据摘要 | 开启 |
| 导出模板 | 默认用哪套导出模板 | 简洁版 |
| 每日快记 | 是否启用 | 关闭（避免负担） |

### F8 模板复用

**目标**：新项目 3 分钟可跑。

**功能点**

1. **项目模板**：保存内容 = 阶段结构 + 任务清单（含工期、归属标签、依赖关系）+ 里程碑 + 需求/缺陷状态配置 + 提醒规则 + 仪表盘布局 + 复盘规则。
2. **两种生成方式**
   - **从模板创建**：选择模板 → 填项目名/负责人/开始日 → 系统按"工期相对偏移"自动换算日期。
   - **从项目另存**：任意项目 → "另存为模板"，可选择是否包含需求/缺陷数据（仅带结构，不带实际内容）。
3. **内置模板（首批 4 套）**
   - 标准研发项目（需求→设计→开发→测试→上线）
   - 迭代交付（双周迭代，含固定节奏节点）
   - 市场活动 / 项目制交付（含排期与物料清单）
   - 空白项目（仅基础配置）
4. **阶段模板**：可单独把某一段流程（如"上线前检查清单"）存为阶段模板，插入到任意项目。
5. **模板版本**：模板改动生成新版本，已用旧版创建的项目不受影响（不自动同步，避免"改模板炸全公司"）。
6. **模板适用范围**：私有（仅自己）/ 团队（本部门）/ 公开（全公司），管理员可下架。

### F9 提醒通知

**触发场景与规则**

| 场景 | 判定 | 默认接收人 | 频率 |
| --- | --- | --- | --- |
| 任务延期 | 今日 > 计划结束 且 状态≠已完成 | 负责人 + 项目负责人 | 延期当天一次，之后每 3 天一次 |
| 任务临期 | 距计划结束 ≤ 2 天且未完成 | 负责人 | 每日 09:00 汇总一条 |
| 任务阻塞 | 状态=阻塞 超过 24h | 项目负责人 | 一次 + 每日汇总 |
| 依赖冲突 | 前置未完成而后置已开始 | 项目负责人 | 即时 |

**降噪规则**：同一任务同一场景 24h 内只推一次；每日汇总优先于单条推送；用户可对单个项目"免打扰"。

### F13 多项目总览（决策 #2 新增，P0）

**目标**：个人同时管多个项目时，一眼看出"哪个要先救"。

**功能点**

1. **顶部汇总条**：进行中项目数 / 总任务数 / 总延期任务数 / 本周待复盘数 / 全局健康度（取最差）。四个数字均带趋势小箭头。
2. **项目卡片墙**：每张卡片显示项目名、健康度灯、双进度条（计划 vs 实际）、距上线天数、延期任务数、最近更新时间。卡片尺寸 320×180，栅格自适应。
3. **排序规则**：默认按"健康度（红→黄→绿）→ 延期数倒序 → 截止日"排序，把最危险的推到左上角（符合驾驶舱阅读习惯）。
4. **筛选与分组**：按状态 / 健康度 / 模板来源 / 自定义标签筛选；支持"仅看我的"（个人形态下即按归属标签过滤）。
5. **跨项目延期清单**：Top 20，字段含所属项目，可一键跳转到对应任务的甘特位置。
6. **卡片进入**：点击卡片 → 过渡进入该项目驾驶舱（旧卡片缩小淡出 + 新页面从卡片位置展开，使用 FLIP，320ms）。
7. **空状态**：无项目时直接给"从模板创建"，不显示空表格。

**视觉复用**：完全沿用第 6 章玻璃面板与光效规范；总览页密度更高——光晕呼吸振幅降至 2px，火焰光带透明度降至 0.22（避免多卡片叠加后过亮）。

## 5. 关键交互原则（"轻量"落地方式）

1. **默认少字段**：新项目只显示 8 个核心字段，其余按需在设置里开。
2. **能内联不弹窗**：列表内直接编辑；只有"删除/归档/变更基线"才二次确认。
3. **一次只问一件事**：新建任务默认只填标题，其余可后补；必填项不超过 3 个。
4. **入口收敛**：全局只有一个"+新建"，下拉选任务/需求/缺陷。
5. **空状态有用**：空项目直接给模板推荐，而不是空白表格。
6. **键盘优先**：列表支持 Tab 切换单元格、Enter 新建、/ 搜索、Esc 关闭。
7. **危险操作可逆**：删除进回收站，30 天内可恢复。

## 6. 视觉风格规范（Visual Design System）

### 6.1 设计定位

**项目作战总览驾驶舱**：深色作战室基调，橙红与暖金构成光效体系，数据面板为玻璃拟态，背景持续流动但绝不喧哗。

一句话原则：**数据是主角，光效是氛围，动效是呼吸。**

**三条视觉纪律（不可违反）**

| 纪律 | 说明 |
| --- | --- |
| 光效只在边缘 | 发光仅用于面板边框、标题、状态指示、图标；正文区域一律低亮背景 + 高对比文字，保证 4.5:1 以上对比度 |
| 颜色必须有语义 | 同一颜色在全系统只有一个含义，不允许"为了好看"随机上色 |
| 动效不表演 | 所有循环动效周期 ≥ 1.5s，禁用闪烁与高频缩放；异常态才允许高频动效，且必须收敛 |

### 6.2 色彩体系（Design Token）

> 本节色值描述**默认主题 ember（橙红暖金）**。第二套主题 ocean（赛博蓝紫）的完整色值与多主题约束见 6.2.1。

**基底**

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg-void` | `#08080C` | 最底层（页面根） |
| `--bg-deep` | `#0E0E14` | 主内容区底色 |
| `--bg-panel` | `rgba(26, 19, 22, 0.55)` | 玻璃面板填充 |
| `--bg-panel-hover` | `rgba(34, 25, 28, 0.65)` | 面板悬浮态 |
| `--bg-inset` | `rgba(0, 0, 0, 0.35)` | 面板内凹区（图表底、输入框） |

**光效（橙红 + 暖金）**

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ember-600` | `#E8410F` | 最深橙红（危险底色） |
| `--ember-500` | `#FF5A1F` | 主橙红（延期、告警、关键操作） |
| `--ember-400` | `#FF7A33` | 橙红亮部（渐变高光） |
| `--amber-500` | `#FFA53D` | 暖金（里程碑、关键路径、标题发光） |
| `--amber-300` | `#FFC978` | 暖金亮（文字内芯） |
| `--glow-ember` | `rgba(255, 90, 31, 0.45)` | 橙红光晕 |
| `--glow-amber` | `rgba(255, 165, 61, 0.38)` | 暖金光晕 |

**状态语义（唯一映射，全系统共用）**

| 语义 | 色值 | 使用场景 |
| --- | --- | --- |
| 正常 / 进行中 | `#3FD8E0`（青） | 任务进行中、健康度绿、依赖正常 |

| 中性 / 已结束 | `#6B5F5A`（暖灰） | 已完成任务条、取消态、网格线 |

**文字**

#### 6.2.1 外观主题（多主题机制）

> 2026-10-26 新增。入口：**设置 → 外观**。本节约束优先级高于 6.2 中对单一色值的描述。

**机制**：两套主题共用**同名 Token**，只换值。切换只改 `<html data-theme>`，纯 CSS 变量生效，不重建 DOM、不重算图表，图表会自动跟随。

| 主题键 | 名称 | 定位 |
| --- | --- | --- |
| `ember` | 橙红暖金（默认） | 即 6.2 全表色值，保持不变 |
| `ocean` | 赛博蓝紫 | 主色蓝 + 次色紫，深蓝黑基底 |

**ocean 主题色值**

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg-void` | `#060A14` | 页面根 |
| `--bg-deep` | `#0A1120` | 主内容区底色 |
| `--bg-panel` | `rgba(17, 26, 44, 0.55)` | 玻璃面板填充 |
| `--bg-panel-hover` | `rgba(24, 35, 58, 0.65)` | 面板悬浮态 |
| `--bg-inset` | `rgba(0, 4, 12, 0.42)` | 面板内凹区 |
| `--ember-600` | `#0B57C7` | 主色暗档 |
| `--ember-500` | `#2E8BFF` | **主色（蓝）** |
| `--ember-400` | `#5BA6FF` | 主色亮档 |
| `--amber-500` | `#7C6BFF` | **次色（紫）** |
| `--amber-300` | `#A996FF` | 次色亮档 |
| `--c-neutral` | `#5E7290` | 中性（灰蓝） |
| `--text-primary` | `#E8F0FF` | 主文字（冷白） |
| `--text-secondary` | `#93A6C4` | 次文字 |
| `--text-dim` | `#5E7290` | 占位符、辅助说明 |

**四条硬约束**

1. **语义色跨主题恒定**：进行中青 `#3FD8E0`、已完成绿 `#48D18A`、阻塞橙 `#FF8C42`、致命红 `#E8410F` 在两套主题中完全一致。理由：颜色即含义，若随主题变化，用户每切一次外观就要重新认一次状态，认知成本高。
2. **优先级色随主题**：P0 = `--ember-500`、P1 = `--amber-500`、P2 = `--c-cyan`、P3 = `--text-dim`。优先级表达的是紧迫度梯度，不是固定含义。
3. **次色档禁止用青色**：冷色系里青色已被「进行中」占用，ocean 次色档改用紫色拉开层次；暖色系可继续靠明度区分（橙红 / 琥珀）。
4. **派生色只定义一次**：光晕、描边、图表辅助色在 `:root` 用 `color-mix(in srgb, var(--原料色) N%, transparent)` 推导，ocean 只需覆盖原料色，派生色自动适配。

**动效开关**：设置 → 外观 → 动效，取值 `on | off`，写入 `settings.motion`。关闭时**同时**停掉 CSS 动画与 rAF 循环（`Motion` / `Particles`），仅保留 120ms opacity 过渡。只关 CSS 而 rAF 仍在跑属于假关闭，会继续耗电。

**实现约束（易错点）**

- SVG 的 `fill="var(--x)"` 作为 XML 属性**无效**，必须写成 `style="fill:var(--x)"`。
- 颜色值禁止拼接透明度后缀（如 `color + '2E'`）。颜色改为 `var(--token)` 后会拼出非法值，整条样式失效——一律改用 `color-mix`。
- 外观数据（`theme` / `motion`）属于 `settings`，会随备份文件导出；旧备份缺这两个字段时按默认值回落，不得报错。

### 6.3 玻璃拟态面板（Glass Panel）

**规格**

- 填充：`--bg-panel` + `backdrop-filter: blur(18px) saturate(140%)`
- 圆角：14px（卡片）/ 18px（大面板）
- 边框：1px 霓虹细边，颜色随状态变化
- 阴影：内高光（顶部 1px 亮线）+ 外扩散光晕
- 内边距：20px（卡片）/ 24px（面板）

**标准实现（渐变描边用伪元素 mask，避免 border-image 性能问题）**

```css
.panel {
  position: relative;
  border-radius: 14px;
  background: var(--bg-panel);
  backdrop-filter: blur(18px) saturate(140%);
  box-shadow:
    inset 0 1px 0 rgba(255, 214, 170, 0.12),
    0 8px 32px rgba(0, 0, 0, 0.55);
  isolation: isolate;
}
/* 霓虹细边框：1px 渐变描边 */
.panel::before {
  content: "";
  position: absolute;
  inset: 0;
  border-radius: inherit;
  padding: 1px;
  background: linear-gradient(
    135deg,
    rgba(255, 138, 76, 0.55),
    rgba(255, 165, 61, 0.18) 42%,
    rgba(255, 90, 31, 0.06) 70%,
    rgba(255, 138, 76, 0.40)
  );
  -webkit-mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0);
  -webkit-mask-composite: xor;
  mask-composite: exclude;
  pointer-events: none;
}
/* 呼吸光晕层：只动 opacity，不动 box-shadow */
.panel::after {
  content: "";
  position: absolute;
  inset: -1px;
  border-radius: inherit;
  box-shadow: 0 0 28px var(--glow-amber), 0 0 64px rgba(255, 90, 31, 0.14);
  opacity: 0.38;
  animation: breathe 3.5s ease-in-out infinite;
  pointer-events: none;
  z-index: -1;
}
@keyframes breathe {
  0%, 100% { opacity: 0.30; }
  50%      { opacity: 0.62; }
}
```

**发光标题**

```css
.panel-title {
  font-size: 15px;
  font-weight: 600;
  letter-spacing: 0.04em;
  color: var(--amber-300);
  text-shadow:
    0 0 8px rgba(255, 165, 61, 0.55),
    0 0 22px rgba(255, 90, 31, 0.35),
    0 0 44px rgba(255, 90, 31, 0.18);
}
```

> 发光仅限 15px 以上标题。正文、表格、数值一律不加 `text-shadow`（会糊）。

### 6.4 透视图标规范（绕 Y 轴向内旋转）

**定义**：所有仪表盘图标统一做 **Y 轴内旋透视**——图标右侧沿 Z 轴向内（远离观察者）后退，形成 2.5D 朝向观察者的倾斜站姿。这是全局唯一的图标姿态，不混用其他角度。

```css
.icon-3d {
  perspective: 520px;
  perspective-origin: 50% 50%;
}
.icon-3d > svg {
  transform: rotateY(14deg) translateZ(0);
  transform-origin: 50% 50%;
  transform-style: preserve-3d;
  filter: drop-shadow(0 0 10px rgba(255, 138, 76, 0.40));
  transition: transform 320ms cubic-bezier(0.22, 1, 0.36, 1);
}
/* 悬浮：向观察者回正，模拟"转向你" */
.icon-card:hover .icon-3d > svg {
  transform: rotateY(6deg) translateZ(6px);
}
```

**约束**

| 项 | 规定 |
| --- | --- |
| 旋转角度 | 统一 14°，允许区间 12°–18°，同一屏内必须一致 |
| 透视距离 | `perspective: 520px`（值越小畸变越强，低于 400px 开始失真） |
| 文字 | **不参与透视**，始终保持水平，保证可读 |
| 厚度感 | 图标底座加一层偏移 2px 的暗色伪元素，模拟方块厚度 |
| 尺寸 | 卡片图标 28px，侧栏导航 24px，大屏 KPI 图标 36px |
| 禁用 | 不对小字号（<14px）图标做透视，会糊成一团 |

### 6.5 背景系统（三层叠加，全屏固定）

层序：`z-index: 0` 装饰层 → `z-index: 1` 内容层。装饰层 `pointer-events: none`。

**第 1 层 · 火焰光带（Fire Bands）**

- 2 个超大渐变光块（尺寸 `160vmax`），`radial-gradient` + `blur(80px)`，`mix-blend-mode: screen`，`opacity: 0.32`
- 色相：橙红 `#FF5A1F` → 暖金 `#FFA53D` → 透明
- 运动：各沿椭圆轨迹做 `translate3d` 位移，周期 60s / 84s，方向相反，制造"流动感"而非"平移感"
- **禁止**动画 `background-position`（会触发全屏重绘）

```css

  0%   { transform: translate3d(-12%, 6%, 0) scale(1); }
  33%  { transform: translate3d(8%, -4%, 0) scale(1.08); }
  66%  { transform: translate3d(14%, 10%, 0) scale(0.96); }
  100% { transform: translate3d(-12%, 6%, 0) scale(1); }
}
@keyframes fireDriftB {
  0%   { transform: translate3d(16%, -8%, 0) scale(1.05); }
  50%  { transform: translate3d(-10%, 12%, 0) scale(0.94); }
  100% { transform: translate3d(16%, -8%, 0) scale(1.05); }
}
```

**第 2 层 · 粒子光点（Particles）**

- 单 Canvas 层，粒子数 **60–80**（按屏幕面积自适应，上限 100）
- 半径 0.8–2.2px，暖金色，透明度 0.15–0.50，各自有相位差
- 运动：向上漂移 8–20px/s + `sin` 横向微摆（幅度 6–14px，周期 4–7s）
- 渲染：`rAF` 限 **30fps**（`if (t - last < 33) return`），`devicePixelRatio` 上限 2
- 越界后从底部重生，透明度需渐入，禁止突然出现

**第 3 层 · 科技网格地面（Grid Floor）**

- 位置：视口底部 38% 高度
- 实现：`perspective(600px) rotateX(62deg)` + `repeating-linear-gradient`（网格间距 48px）
- 前景渐隐：`mask-image: linear-gradient(to top, #000 0%, transparent 78%)`
- 运动：整层 `translate3d(0, 0, 0)` → `translate3d(0, 48px, 0)` 循环 24s，模拟地平线推进（一格一格走，正好等于间距，保证无缝）
- 透明度 0.12，颜色 `--text-dim`

```css
.grid-floor {

  left: -20%; right: -20%; bottom: 0;
  height: 38vh;
  background-image:
    repeating-linear-gradient(90deg, rgba(107,95,90,.55) 0 1px, transparent 1px 48px),

  from { transform: perspective(600px) rotateX(62deg) translateY(0); }
  to   { transform: perspective(600px) rotateX(62deg) translateY(48px); }
}
```

## 7. 交互动效规范（Motion System）

### 7.1 总则

**四条硬规则**

1. **只动 `transform` 与 `opacity`**。禁止动画 `width` / `height` / `top` / `left` / `box-shadow` / `backdrop-filter` / `background-position`（会触发布局或大面积重绘）。
2. **统一缓动**：`cubic-bezier(0.22, 1, 0.36, 1)`（快入慢出、有惯性收尾）。
3. **统一时长档**：120ms（微反馈）/ 320ms（面板与视图）/ 600ms（数据更新与入场编排）/ 3.5s（呼吸循环）。
4. **一次只动一个主角**。同一时刻用户注意力只该被一个强动效牵引。

### 7.2 静默空闲状态（Idle）

系统在无操作时**不是静止的，而是在缓慢呼吸**。所有动效必须柔和、可预期、永不出戏。

#### 7.2.1 全局 sin 上下缓动

所有面板与卡片注册到统一缓动循环，各自分配相位，形成"波浪式"起伏而非整齐划一的跳动。

`y(t) = A · sin(2π · t / T + φ)`

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `A` 振幅 | 2–4px（面板 3px，卡片 2px） | 超过 5px 会显得"飘" |
| `T` 周期 | 6–9s（按元素索引在区间内取不同值） | 避免同频共振 |
| `φ` 相位 | `index × 0.7 rad` | 相邻元素错峰，形成波浪 |
| 驱动 | **单个 rAF 统一驱动**，不用每个元素各自 CSS 动画 | 避免相位撞车 + 便于统一降级 |

```js
// 统一缓动循环器：一个 rAF 驱动所有注册元素
const easers = new Map(); // el -> { amp, period, phase }

function tick(t) {
  easers.forEach((cfg, el) => {
    const y = cfg.amp * Math.sin((2 * Math.PI * t) / cfg.period + cfg.phase);
    el.style.transform = `translate3d(0, ${y.toFixed(2)}px, 0)`;
  });
  rafId = requestAnimationFrame(tick);
}

function register(el, i) {
  easers.set(el, {
    amp: 2 + (i % 3),              // 2~4px
    period: 6000 + (i % 4) * 900,  // 6.0~8.7s
    phase: i * 0.7,                // 相位错开
  });
}
```

> 注意：缓动 `transform` 会覆盖元素自身的其他 `transform`。若元素需要 hover 上浮，用**外层容器做 sin 缓动，内层做 hover**，两层分离。

#### 7.2.2 面板光晕呼吸

- 周期 **3.5s**，`ease-in-out`，无限循环
- 变化量：`opacity` 0.30 ↔ 0.62（只在伪元素光晕层上动，不动 `box-shadow`）
- 相邻面板相位错开 0.6s，形成此起彼伏的"呼吸"

#### 7.2.3 图表缓慢流动

| 元素 | 表现 |
| --- | --- |
| 折线曲线 | `stroke-dashoffset` 线性前移，8s 一循环，视觉速度 ≈ 12px/s |
| 数据点 | 沿曲线路径微幅漂移，周期 4s，位移 ≤ 2px |
| 流光头 | 末端 3 个光点依次前移，4s 周期，透明度递减 |
| 环形进度 | 稳态不循环动画，仅在数据变更时 600ms 过渡（避免视觉噪音） |

#### 7.2.4 背景持续位移

| 层 | 周期 | 表现 |
| --- | --- | --- |
| 火焰光带 A | 60s | 椭圆轨迹漂移 + 轻微 scale 1.0↔1.08 |
| 火焰光带 B | 84s | 反向漂移，与 A 交叠产生流动层次 |
| 粒子 | 持续 | 向上漂移 + sin 横摆，30fps |
| 网格地面 | 24s | 匀速向下推进一格（48px），无缝循环 |

#### 7.2.5 Idle 状态禁令

| 禁止项 | 原因 |
| --- | --- |
| 任何 < 1.5s 周期的循环 | 会形成闪烁，长时间注视导致疲劳 |
| 缩放呼吸（`scale` 循环） | 文字会持续发虚，观感廉价 |
| KPI 数字持续跳动 | 制造虚假紧迫感，与"沉稳"基调冲突 |
| 随机闪点 / 灯泡式闪烁 | 廉价且抢数据焦点 |
| 突然出现的元素 | 必须伴随 opacity 与位移渐入 |

#### 7.2.6 交互唤醒与回落

- 鼠标移入主区 → L2 元素 sin 振幅降至 1px（避免干扰阅读）
- 用户 5s 无操作 → 恢复正常振幅
- 页面切到后台（`visibilitychange`）→ 暂停全部 rAF，火焰动画 `animation-play-state: paused`

### 7.3 点击交互与视图切换

#### 7.3.1 面板点击展开 / 收缩（320ms）

**技术要求：禁止直接动画 `width`/`height`。** 采用 FLIP 或固定占位方案：

| 方案 | 做法 | 适用 |
| --- | --- | --- |
| **FLIP（推荐）** | 先记录首帧尺寸 → 切到末态布局 → 用 `transform: translate + scale` 反向抵消 → 下一帧播放归零 | 面板尺寸变化 |
| 内容跟随 | 内容层 `opacity` 0→1，延迟 80ms（等容器基本到位再显字） | 所有展开 |

```css
.panel {
  transition:
    transform 320ms cubic-bezier(0.22, 1, 0.36, 1),
    opacity   320ms cubic-bezier(0.22, 1, 0.36, 1);
  will-change: transform, opacity; /* 动画结束由 JS 移除 */
}
```

**交叉约束**：展开时外层光晕与内容同步，但内容透明度曲线更"慢半拍"（延迟 80ms），视觉上形成"容器先张开、内容再浮现"的层次。

#### 7.3.2 Tab 视图切换（交叉淡化 + 上浮）

| 阶段 | 旧内容 | 新内容 |
| --- | --- | --- |
| 0–160ms | `opacity: 1 → 0`，`translateY: 0 → -8px`（轻微上移淡出） | 等待 |
| 120–440ms | — | `opacity: 0 → 1`，`translateY: 12px → 0` |

- 两段重叠约 40ms，形成"交叉"而非"中间黑屏"
- 总时长 440ms，全程只动 transform + opacity
- 优先使用 View Transitions API（`document.startViewTransition`），不支持时回退到上述手写实现
- 切换期间面板不参与 sin 缓动（避免两套 transform 叠加冲突）

#### 7.3.3 卡片悬浮微交互

| 属性 | 值 | 时长 |
| --- | --- | --- |
| 位移 | `translateY(0 → -2px)` | 200ms 进入 |
| 边框亮度 | 描边渐变 `opacity 0.35 → 0.78` | 200ms |
| 光晕 | `opacity +0.20` | 200ms |
| 回落 | 全部反相，**320ms**（回比去慢，更柔） | 320ms |

- 卡片内透视图标同步 `rotateY(14deg → 6deg)`，模拟"转向你"（320ms 同缓动）
- 同组卡片中 hover 一张时，其余降至 `opacity: 0.78`（聚焦效应），不做位移

#### 7.3.4 点击反馈

- 按下：`scale(0.995)`，60ms
- 松开：回 1.0，120ms
- 按钮类另加内发光层 `opacity 0 → 0.35`，120ms

### 7.4 状态与异常动效（低频、有节制）

| 场景 | 动效 | 约束 |
| --- | --- | --- |
| 健康度转红 | 边框转为 `--ember-500` + 脉冲 **3 次后停止**，转常亮 | 永不无限脉冲 |
| 任务延期 | 甘特条末端红色斜纹 + 卡片一次 200ms 亮度呼吸 | 不做闪烁 |
| 致命缺陷新增 | 指标卡光带脉冲 1.2s × 3 次，同时右侧滑入 Toast | 同一缺陷只提示一次 |
| 复盘待写 | 日历格淡金色小点 + 一次缩放回弹（1 → 1.08 → 1，320ms） | 不循环、不用红色 |
| 数据更新 | 数值滚动 600ms；条形 `scaleX` 320ms；环 `dashoffset` 600ms | 同一面板 500ms 内合并更新，避免连续抖动 |
| 加载 | 骨架屏 + 微光横扫（2s 一次，`translateX`）；超 3s 转错误态 | 不做旋转 loading 大转盘 |

> **异常动效的唯一目的**：让主人一眼看到"哪里出事了"。看到即止，不制造焦虑。

### 7.5 性能约束（硬性验收项）

| 类别 | 要求 |
| --- | --- |
| 属性白名单 | 仅 `transform` / `opacity`；`filter` 仅用于静态发光，禁止参与动画 |
| 合成层 | 动画元素提前加 `will-change: transform, opacity`，动画结束**立即移除**；同屏 `will-change` 元素 ≤ 8 个 |
| 帧率目标 | 桌面 60fps；低端设备 ≥ 45fps；掉帧判定：连续 3s FPS < 45 |
| 降级策略 | FPS 45–55 → L3 降为 15fps；FPS < 45 → 关闭 L3（火焰/粒子/网格），保留 L1/L2；FPS < 30 → 关闭 L2 循环，仅保留数据过渡 |
| 后台暂停 | `document.hidden` 时暂停所有 rAF 与 CSS 动画 |
| 粒子规模 | 60–80 个（上限 100），DPR ≤ 2，30fps |
| 图表渲染 | 数据点 > 200 时切 Canvas 渲染；< 200 用 SVG（便于交互与动效） |
| 首屏 | 装饰层（L3）在 `requestIdleCallback` 中挂载，不阻塞 LCP；LCP ≤ 2.0s |
| 内存 | 长时间运行（8h）内存增长 ≤ 15%，粒子与图表实例需正确销毁 |
| 布局抖动 | 全站 CLS < 0.05 |

### 7.6 无障碍与降级

| 条件 | 行为 |
| --- | --- |
| `prefers-reduced-motion: reduce` | 关闭 L2/L3 全部循环动画；保留 120ms 以内的透明度淡入；sin 缓动归零 |
| 系统省电模式 / 电量 < 20% | 关闭 L3 装饰层 |
| 低端设备（`navigator.hardwareConcurrency ≤ 2`） | 初始即按 L1 + 简化 L2 渲染 |
| 键盘操作 | 焦点环必须可见（2px 暖金 + 2px 偏移），焦点切换时 `scrollIntoView` 平滑 |
| 高对比度需求 | 提供"降光效"开关：关闭发光与玻璃模糊，使用纯色面板，文字对比度 ≥ 7:1 |

### 7.8 视觉与动效验收标准

1. 静置 60s 观察，无任何元素出现闪烁、跳变或节奏 < 1.5s 的循环。
2. 全屏面板的 sin 缓动相位互不相同，肉眼可见"波浪式"起伏而非整齐上下。
3. 面板光晕在 3.5s 周期内平滑明暗，无台阶感（`box-shadow` 不参与动画）。
4. 连续切换 Tab 20 次，无内容重叠残留、无黑屏间隙、无布局抖动。
5. 展开面板时，DevTools Performance 面板无 Layout / Paint 阶段的持续开销（仅 Composite）。
6. 甘特图 1000 任务 + 全部背景动效同时运行，FPS ≥ 45。
7. 开启系统"减少动效"后，所有循环动画停止，功能完全可用。
8. 粒子数、`will-change` 元素数不超过规定上限（同屏 ≤ 8）。
9. 页面切后台后 CPU 占用降至接近 0（rAF 已暂停）。
10. 深色背景下正文文字对比度 ≥ 4.5:1，告警色文字 ≥ 4.5:1。

### 11.1 「仅供个人使用」带来的连锁调整（已按此收敛）

单用户形态意味着原设计中所有"多人协作"假设需下调，本节为强制约束：

| 原设计 | 单用户下的调整 |
| --- | --- |
| 角色权限体系（原第 3 章，已删除） | 无 RBAC、无角色概念，全部功能对本机用户开放 |
| 提交的"确认人 / 退回"流程 | 整体转为**自我复盘**：不设审批、不设确认人，只做记录与导出（见 F7） |
| 提交缺漏提醒接收人（本人 + 确认人） | 改为「复盘待写」，仅推给本人，一次即止 |
| 任务负责人（原按成员统计工作量） | 保留为**归属标签**：仅作分类标签，不代表登录用户；仪表盘不再提供按归属统计的"负载"视图（决策 #8） |
| 并发编辑（200 人乐观锁） | 降级为单端编辑，仅保留版本号防误覆盖 |
| 「链接分享」权限 | 简化为本地导出 / 截图，不做在线只读分享 |

### 11.2 仍需主人拍板

1. **任务归属维度**：既然是个人使用，任务上的"负责人"是否改为"归属标签"（如"我 / 外包A / 待定"）？还是保留人名仅作备注？
2. **多项目总览的数据密度**：F13 是只做"项目卡片墙 + 健康度灯"，还是需要跨项目甘特叠加？前者轻，后者重，建议先做前者。
3. **数据存在哪**：个人使用形态下，存本地（浏览器 IndexedDB / 本地 SQLite）还是云端？本地更私密、零成本，但换设备要导出导入；云端可多端同步但有账号与运维成本。
4. **导出是否需要"客户版"**：对外汇报时是否要一套自动隐藏任务内部名称、只留分类统计的脱敏模板？
