## 二、缺陷清单

### BUG-1【一般】≤1440px 断点：仪表盘末行只剩半宽面板，右侧整块空出

- **现象**：窗口宽度 ≤1440px 时，「风险与提醒」被 `@media (max-width:1440px)` 从 span 4 放大到 span 6，独占一行的左半，右侧同尺寸空白（1440 下 635×346px ≈ 22 万 px²；1366 下 598×240px）。
- **复现步骤**：打开 `app/index.html` → 窗口宽拖到 1440（或 1366 / 1280）→ 进「仪表盘」→ 滚到最底部。

  | 1600 | 12/12/12/12（0 处缺口） | **12/12/12（0 处缺口）** |
  | 1440 | 6/12/12/12/12/12/**6**/12（2 处） | 6/12/12/**6**/12/**6**（3 处） |
  | 1366 | —（未测，快照无此宽度） | 6/12/12/**6**/12/**6**（3 处） |
  | 1280 | 6/12/12/12/12/12/6/12（2 处） | 6/12/12/6/12/6（3 处） |

  1440 改造后逐行实测（`offsetWidth/offsetLeft` 布局盒，已排除装饰性 `sin` 浮动 transform 干扰）：


## 五、≤1440px 断点的独立判定（brief 特别要求）

- **事实**：改造前 1440/1280 下就有 2 处「半宽尾行」（第 1 行「进度对比」独行、第 7 行「复盘状态」独行）；改造后变成 3 处，新增的一处在**最后一行**（「风险与提醒 635×346」右侧 635×346 空白）。1366 同样如此。
- **机制判断**：不是这次新造出来的机制 —— 是 `≤1440` 把 `.c4→span 6 / .c8→span 12` 的既有映射，遇上「奇数个 span-4 面板」时的必然结果。本次只是把面板数从 9 减到 7、重排后把半宽面板挤到了末行。
- **性质判断**：**这是本次改动引入的「可见退化」**——改造前末行是满宽的，用户视线终点不会有空洞；改造后有了。但它**不含功能影响**：无横向溢出（`scrollWidth == innerWidth`）、无内容裁切、无错位，只是观感。按 brief 的严重度定义归 **一般（体验瑕疵）**。
- **我的建议**：**不该按「既有问题、可不管」放过**。成本极低（≤1440 给「风险与提醒」加 `span 12`，或把它与「复盘状态」调成相邻），收益是恢复「末行满宽」的视觉收口。若产品接受半宽尾行，则需在 PRD 的板式图里写明 ≤1440 的降级规则，避免下一轮又当缺陷报。
